## 未完成事项(按优先级)

### P1 · 内容观点生成层产品化

**问题**:当前已经有观点包框架,但还没有用真实 JSON 跑通每日观点包,也没有确认下游 PPT/HTML 需要的字段是否完整。

**方案**:先用一份 `snapshot_YYYY-MM-DD_lite.json` 生成 `viewpoint_pack`,人工检查字段、证据绑定、客户经理可转述版和 PPT 短句。确认后再写自动生成脚本。

### P2 · 议题 2:AI 替代公式打分

**问题**:Excel 的 IF 阈值打分产出的是"数据陈述"(如"PPI 为 0.5%"),AI 基于这些数据写的分析也是描述性的,缺少"因果与判断"。

**方案**:在 Python 脚本里对关键指标(PPI/CPI/PMI/信贷等有解释空间的)调用 Anthropic API,让 AI 根据上下文生成因果判断(如"PPI 转正或部分受油价推升,成色待察"),替换 JSON 的 `auto_view` 字段。利率、汇率等纯价格指标仍用公式。

**风险**:
- 每次导出 JSON 多一笔 API 成本,要设置 fallback
- AI 产出可能偶尔偏离规则,要加 prompt 约束

### P3 · 展示 HTML 产品线产品化

**问题**:当前全量展示 HTML 仍是历史单文件样例,观察台也仍是测试工具形态。两者已经归入同一展示 HTML 产品线,但还没有统一生成流程和模板边界。

**方案**:在 `products/display_html/` 下继续沉淀生成脚本、模板和测试。全量展示 HTML 从 JSON + `viewpoint_pack` 自动组装;观察台继续服务于指标历史变化查看和日报选指标。

### P4 · 日报 PPT 产品线产品化

**问题**:日报 HTML/PDF 试验线已下线,后续需要直接构建 PPT,但固定版式、字段、动态数据绑定和客户经理可转述层还需要重新梳理。

**方案**:在 `products/daily_ppt/` 下固定 PPT 组件规范、进入日报的指标字段、同口径 JSON/历史序列接入方式,并沉淀生成脚本和最小样例。

### P5 · 飞书推送集成(第 6 环节)

每日定时,将生成的 HTML 或摘要推送至投研团队飞书群。打通"Wind 刷新 → 团队看到报告"的最后一公里。

### P6 · 知识库文档的可读性优化

**现状**:`skills/excel_maintenance.md` / `skills/indicator_management.md` 里的行号表和权重表密集,长期维护时易出错。

**方案**:
- 把"行号-指标-节点-权重"关系抽出成结构化数据(JSON),文档里只引用不硬编码
- 行号表应以 Python 脚本的 NODE_INDICATORS 为唯一真相来源
